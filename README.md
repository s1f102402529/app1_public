# app1_public

BabyLogは、授乳・睡眠・おむつ交換などの日々の育児記録を残し、あとから振り返るためのDjangoアプリです。記録の入力だけでなく、一覧・期間別表示や集計、予測を通じて、日々の記録を見やすく整理することを目的に開発しています。

このリポジトリは就職活動用ポートフォリオです。Dockerを使ってローカルで動作を確認できます。インターネットに公開して運用するための設定ではありません。

## 主な機能

- ユーザー登録、ログイン、ログアウト
- 必要に応じたDjango管理者アカウントの作成
- 授乳、睡眠、おむつ交換、排泄、体温、その他の記録の追加・編集・削除
- ユーザーごとの記録分離
- 記録一覧、日別・月別表示
- 直近の記録をもとにした授乳・睡眠時刻の予測
- 週次の記録グラフと、期間を選択できる分析画面
- 選択した期間の集計情報を使ったAIアドバイス
- 閲覧用のデモアカウントと架空のサンプル記録

デモアカウントでは、記録の追加・編集・削除はできません。通常登録したユーザーは、自分の記録を管理できます。

## 使用技術

- Python、Django
- SQLite（育児記録の保存先）
- Docker、Docker Compose
- Requests（AI APIとのHTTP通信）
- Bootstrap 5（画面のスタイル）

## 開発で工夫した点

- 記録をユーザーに紐づけ、画面の表示・編集・削除をログイン中のユーザーの記録に限定しています。
- 予測では、記録が十分にある場合は過去の記録間隔を使い、不足する場合は標準的な時間を使う構成です。予測は参考情報であり、医療的な判断を行うものではありません。
- AI分析では、個々の記録一覧ではなく、選択期間の日別集計を送信します。メモやユーザー識別情報は送信せず、入力サイズやサンプル数にも上限を設けています。
- デモデータは専用コマンドで作成し、デモ用アカウントを読み取り専用にしています。
- テストではAI API呼び出しをモックし、テスト実行による外部API通信を避けています。

## 必要な環境

- Docker
- Docker Compose
- デモ利用のみの場合、外部AI APIキーは不要です。
- AI機能を試す場合は、利用可能なAI APIキーが必要です（「AI機能について」を参照）。

## ローカルでの起動

以下は、GitHubから取得した新しい作業コピーでの手順です。既存の個人用データベースをコピーせずに進めてください。

### 1. 環境変数ファイルを用意する

プロジェクトのルートで、サンプルを `.env` にコピーします。

```sh
cp .env.example .env
```

`.env` を開き、`DJANGO_SECRET_KEY` と `POSTGRES_PASSWORD` の例の値を、それぞれ別のランダムな値に置き換えてください。`DJANGO_SECRET_KEY` の生成例は次のとおりです。コマンドを実行するたびに異なる値が生成されます。

```sh
python3 -c "import secrets; print(secrets.token_urlsafe(50))"
```

生成した値をソースコードやREADMEに貼り付けたり、`.env` をGitにコミットしたりしないでください。`.env.example` は説明用のダミー値だけを含みます。

デモボタンを表示するため、`.env` の `DEMO_ACCOUNTS_ENABLED` は `true` にします。`.env.example` にはこの設定を含めています。

### 2. Docker Composeで起動する

プロジェクトのルートで実行します。

```sh
docker compose up --build -d
```

### 3. SQLiteデータベースを初期化する

Djangoのマイグレーションを適用します。

```sh
docker compose exec backend python manage.py migrate
```

次に、デモアカウントと架空のサンプル記録を作成します。

```sh
docker compose exec backend python manage.py initialize_demo_accounts
```

### 4. ブラウザーでアプリを開く

ブラウザーで <http://localhost:8000/> を開きます。ログイン画面に表示されるボタンを使って、次のどちらかのデモアカウントにログインできます。

- 「デモ1：短期間のデータで試す」：直近7日分
- 「デモ2：長期間のデータで試す」：直近45日分

デモアカウントに入力するユーザー名やパスワードはありません。各ボタンからログインしてください。デモボタンが表示されない場合は、`.env` の `DEMO_ACCOUNTS_ENABLED=true` を確認し、設定変更後にコンテナを再作成してください。

### データベースについて

Djangoは `backend/db.sqlite3` を育児記録の保存先として使用します。ComposeにはPostgreSQLサービスも定義されていますが、現在のDjango設定はPostgreSQLに接続していません。Compose起動時にはPostgreSQLも起動し、`POSTGRES_PASSWORD` が必要になりますが、現在のアプリの育児記録はSQLiteに保存されます。PostgreSQLのボリュームはSQLiteデータのバックアップではありません。PostgreSQLの5432番ポートはホストのlocalhostにのみ公開されます。既存のPostgreSQLボリュームを再利用する場合、初期化時のパスワードが残っていることがあり、`.env` の値を変更してもDB内のパスワードは更新されません。

新しい作業コピーでは、マイグレーション後にデモ初期化コマンドを実行すると、デモアカウント2つと架空のサンプル記録が作られます。既存の個人用SQLiteデータベースに対して初期化コマンドやマイグレーションを実行しないでください。マイグレーション `0005_babylog_user` は既存の所有者なし記録をユーザー `admin` に割り当てようとし、該当記録があるのに `admin` が存在しない場合は停止します。既存データがある場合は、マイグレーション前にSQLiteファイルをバックアップし、割り当て先を確認してください。

管理者アカウントを作成する場合は、次を実行します。

```sh
docker compose exec backend python manage.py createsuperuser
```

アプリ内の育児記録を保存するデータベースはSQLiteです。PostgreSQLサービスをアプリで利用する構成ではありません。

## デモアカウント

- ログイン画面のデモボタンは、`DEMO_ACCOUNTS_ENABLED=true` のときだけ表示されます。無効の場合はデモログインもサーバー側で拒否されます。
- 初期化コマンドは `babylog-demo-short` と `babylog-demo-long` を作成し、直近7日分・45日分の架空データを用意します。
- デモユーザーにはログイン用パスワードが設定されず、ログイン画面のボタンからログインします。
- コマンドを再実行すると、デモ専用マーカー付き記録を同期します。通常ユーザーやマーカーのない記録は変更・削除しません。
- 既に同名の通常ユーザーが存在する場合は、そのユーザーをデモ扱いにせず、コマンドは処理を停止します。
- デモアカウントは閲覧専用で、記録の追加・編集・削除をサーバー側でも拒否します。分析・予測・AIアドバイスは利用できます。

## AI機能について

AIアドバイス機能は、INIAD生向けに提供されているAI APIを利用する設定です。現在の接続先は `docker-compose.yml` に設定されています。INIAD生以外の方は、そのAPIの利用権限や利用環境がない場合、AI機能を利用できません。APIキーの取得方法や利用条件について、このリポジトリでは確認できていない情報を案内していません。

AI機能を利用するには、利用権限のあるAI APIキーを `.env` の `AI_API_KEY` に設定する必要があります。APIキーを用意できない場合、AIアドバイスは利用できませんが、ユーザー登録、記録の追加・表示・編集・削除、分析画面、予測機能など、コード内で外部AI API呼び出しを必要としない基本機能は確認できます。

`AI_MODEL` は任意で、未設定または空の場合は `gpt-6-luna` が使われます。`AI_API_URL` は現在 `docker-compose.yml` 側に設定されており、`.env` からは読み込まれません。AI APIはResponses API互換の接続先を想定しています。

AI分析では「直近24時間」「過去7日間」「過去30日間」から期間を選べます。24時間は現在時刻からの直近24時間、7日・30日は日本時間の当日を含む暦日範囲です。期間集計では授乳、睡眠、おむつ交換、排泄、体温などを扱い、未記録を実績ゼロとはみなしません。期間の前半と後半を比較できる場合は、完了した日を対象に1日あたり平均を比較します。

AI分析を実行すると、選択した期間の日別集計などが外部AI APIへ送信されます。個別記録一覧、メモ、ユーザー識別情報は送信対象に含めない設計です。授乳時刻や体温値のサンプルは1日あたり最大2件、送信するJSON全体は32 KiB以下に制限されています。通信タイムアウトは接続5秒・応答45秒で、自動再試行はありません。AI結果はユーザーと期間ごとのDjangoセッションに保持し、育児記録には書き込みません。外部サービスへのデータ送信であることを理解したうえで利用してください。利用料金や利用枠が発生する場合があります。

AIの回答は、記録の振り返りを支援するもので、医療診断や健康状態の判定ではありません。数値だけから健康状態を判断する用途には使用しないでください。

## テスト

テストではAI API呼び出しをモックします。次のコマンドはテスト用の一時データベースを使用します。

```sh
docker compose run --rm --no-deps backend python manage.py test
docker compose run --rm --no-deps backend python manage.py check
docker compose run --rm --no-deps backend python manage.py makemigrations --check --dry-run
```

テスト対象には、ユーザー登録・ログイン、記録のユーザー分離、日別・月別表示、分析・予測、デモログインと読み取り専用制御、AI入力・エラー・レポート表示が含まれます。

## 注意事項

- `.env` と `backend/db.sqlite3` は公開リポジトリに含めないでください。`.env` には秘密情報、SQLiteには個人の育児記録が含まれる可能性があります。
- `.env.example` の秘密値はダミーです。起動前に各自の値へ置き換えてください。実際のAPIキーやパスワードを公開しないでください。
- 現在のDjango設定は開発用です。`DEBUG=True`、空の `ALLOWED_HOSTS`、HTTPSリダイレクト/HSTSやSecure Cookieの未設定など、本番運用に必要な設定が不足しています。Docker Composeも本番運用を想定した構成ではありません。インターネットへ公開して運用しないでください。
- PostgreSQLの5432番ポートはホストのlocalhostにのみ公開されています。PostgreSQLサービスを別用途で使用する場合も、公開ネットワークにポートを開放しないでください。
